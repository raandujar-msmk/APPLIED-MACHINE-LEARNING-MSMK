¿Qué es la Containerización?

Imagina que quieres enviar software de tu ordenador al de un amigo (o a un servidor). En tu ordenador funciona bien, pero en el suyo falla porque le faltan librerías o tiene una versión diferente de Windows/Linux.

La solución: Meter el software y todo lo que necesita para funcionar (código, librerías, configuraciones) en una caja estandarizada.

📦 El Contenedor: Es esa caja. Es ligero, portátil y se ejecuta igual en cualquier lugar.

Arquitectura: Virtualización vs Containerización

La diferencia clave es que los contenedores comparten el núcleo (kernel) del Sistema Operativo, mientras que las VMs necesitan un SO completo cada una.

Máquina Virtual (Pesada)

App A + Librerías
Guest OS (GBs)
Hypervisor
Sistema Operativo Host
Infraestructura (Hardware)

Contenedor (Ligero)

App A + Librerías
App B + Librerías
Motor Docker (Container Engine)
Sistema Operativo Host
Infraestructura (Hardware)

Nota como los contenedores se saltan la capa del "Guest OS", ahorrando gigabytes de espacio y tiempo de arranque.

Imagen vs. Contenedor

Esta es la distinción más importante en Docker.

📄 IMAGEN
(Solo lectura)
➜
comando
run
➜
📦 CONTENEDOR
(En ejecución)
  • La Imagen: Es el plano, la receta o la plantilla. Es estática. (Ej: La clase `Coche` en programación).
  • El Contenedor: Es la instancia viva de esa imagen. Puedes tener muchos contenedores de la misma imagen. (Ej: El objeto `miFerrari` creado desde la clase `Coche`).
